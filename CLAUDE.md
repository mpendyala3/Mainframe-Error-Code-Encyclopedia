# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Stack

Static site: plain HTML, CSS and vanilla JavaScript, generated by a dependency-free Node script. No package.json,
no framework. Hosted on GitHub Pages from the `main` branch root at
`https://mpendyala3.github.io/Mainframe-Error-Code-Encyclopedia/` (a project site, so everything lives under that
base path). Pushing to `main` deploys.

## Commands

```bash
node tools/build.js     # regenerate every page from data/
node tools/check.js     # entries, links, CSP hygiene, sitemap; exits 1 on any problem
node tools/serve.js     # http://localhost:8080/Mainframe-Error-Code-Encyclopedia/ (mimics Pages, serves 404.html)
```

Always run build then check after changing data, the generator, CSS or JS, and commit the generated files.

## Architecture

- `data/categories.json`: the 15 categories in nav order (`key`, `label`, `title`, `heading`, `description`, `intro`).
  `label` is the short nav name and must be 10 characters or fewer from A-Z, 0-9 so it can be drawn as a banner.
- `data/<key>.json`: the entries for one category. Schema, all strings, all required:
  `{ code, title, category, severity, description, cause, fix, example }`, `severity` is `ERROR`, `WARNING` or `INFO`.
  `category` is the class shown as a filter chip on the category page.
- `tools/build.js` writes: `index.html`, `404.html`, `pages/<key>.html`, `codes/<slug>.html`, `assets/codes.json`
  (search index and entry text), `sitemap.xml`, `llms.txt`. Never edit those by hand.
- Slugs: DB2 codes become `sqlcode-805` / `sqlcode-plus-100`; anything else is lower-cased with punctuation turned
  into hyphens. A slug collision gets the category key appended (`u0016-vendor`). Slugs are public URLs: do not change the rule.
- `js/theme.js` runs synchronously in `<head>` (saved theme before first paint). `js/app.js` is deferred and does
  search, the in-page entry dialog, category filters, copy buttons and keyboard shortcuts.
- `css/main.css`: all colour comes from the tokens at the top; light is green-bar paper, dark is a 3270 screen.

Pages work without JavaScript: every row is a real link to `codes/<slug>.html`. With JavaScript, a click opens the
same content in a `<dialog>` once `assets/codes.json` has loaded; until then the link simply navigates.

## Rules that must hold

- **CSP**: every page sets `script-src 'self'; style-src 'self'` and `default-src 'none'` through a meta tag
  (GitHub Pages cannot send headers). No inline scripts, no inline `style=""`, no inline event handlers, no
  third-party hosts. JSON-LD blocks are fine. `tools/check.js` enforces this.
- **No innerHTML.** `app.js` builds DOM with `h()` and `textContent`; the generator escapes everything with `esc()`.
- **Cache busting**: the generator stamps a content hash as `?v=` on CSS, JS and the JSON index. Rebuild after
  any change to those files, otherwise browsers keep the old ones.
- `404.html` uses absolute `/Mainframe-Error-Code-Encyclopedia/` paths because Pages serves it at any depth.
  If the site moves to a custom domain, change `ORIGIN` and `BASE` at the top of `tools/build.js` and in
  `tools/check.js` / `tools/serve.js`.
- The banner lettering comes from the `GLYPHS` table in `tools/build.js` (5x7 cells, 35 characters each). A code with
  a character that has no glyph, or longer than 10 characters, falls back to plain text.

## Adding content

- New entry: add it to `data/<key>.json`, build, check.
- New category: add it to `data/categories.json`, create `data/<key>.json`, build, check.
- The home page shortcuts and FAQ are the `MOST_WANTED` and `FAQ` lists at the top of `tools/build.js`.

## Environment

Windows 11. Git Bash and PowerShell both work; Node is installed, Python is not.
